# Feature Specification: 游戏地球沉浸体验优化

**Feature Branch**: `001-optimize-earth-experience`

**Created**: 2026-07-13

**Status**: Draft

**Input**: User description: "优化游戏地球首屏布局与视觉设计，提升旋转、缩放和国家切换性能，修复国家标记越界、切换失败与闪屏问题。"

## User Scenarios & Testing *(mandatory)*

### User Story 1 - 首屏以游戏地球为主角 (Priority: P1)

作为进入 Earth Explorer 的用户，我希望无需先滚动页面就能看到完整、足够大的游戏地球及其核心操作，让我立即理解这是一个以地球为核心的探索产品并开始交互。

**Why this priority**: 当前标题、说明和统计区域占据过多首屏空间，地球仅显示一部分，直接破坏产品的核心入口和第一印象。

**Independent Test**: 分别以 1280×720、1440×900 和 1920×1080 的桌面视口首次进入 Earth Explorer，确认无需滚动即可看到完整的主探索画布、地球主体、主要控制入口和必要的国家信息入口。

**Acceptance Scenarios**:

1. **Given** 用户从游戏星图进入 Earth Explorer，**When** 页面完成首屏呈现，**Then** 主探索画布高度至少占可见视口的 70%，且地球主体不被标题区、统计区或页面边缘截断。
2. **Given** 用户使用任一目标桌面视口，**When** 页面首次打开且未进行滚动，**Then** 用户可以看到地球主体、缩放/重置等核心控制和国家信息入口，并能直接开始旋转或选择国家。
3. **Given** 用户调整浏览器窗口尺寸，**When** 布局重新适配，**Then** 地球仍保持为最大的视觉区域，标题、统计和辅助信息不会重新挤占主要探索空间。

---

### User Story 2 - 流畅操控与稳定切换 (Priority: P1)

作为正在探索的用户，我希望旋转、缩放、聚焦和切换国家时持续顺滑，操作能及时响应，且不会出现卡顿、闪屏、空白状态或切换失败。

**Why this priority**: 地球交互是产品的核心行为；明显低帧率和不可靠的国家切换会使整个探索流程不可用。

**Independent Test**: 在基准设备和目标桌面视口下连续旋转、缩放 30 秒，再依次和快速切换多个国家，记录可见响应、帧率、切换完成时间和最终选中状态。

**Acceptance Scenarios**:

1. **Given** 地球已完成首屏呈现，**When** 用户连续拖动旋转并交替放大、缩小 30 秒，**Then** 交互保持连续，没有持续性掉帧、明显冻结或输入失去响应。
2. **Given** 用户点击一个不同国家的快捷按钮或国家列表项，**When** 切换开始，**Then** 100 毫秒内出现可见响应，并在 700 毫秒内稳定呈现目标国家及其对应信息。
3. **Given** 用户在 3 秒内连续选择至少 10 个国家，**When** 最后一次选择完成，**Then** 最终聚焦国家、国家标题、统计信息和游戏标记全部对应最后一次选择，且没有失败、回跳、空白帧或整屏闪烁。
4. **Given** 国家切换动画尚未结束，**When** 用户发起新的国家选择，**Then** 新选择接管当前流程，并以最后一次用户意图作为唯一最终状态。

---

### User Story 3 - 标记准确位于所选国家 (Priority: P1)

作为按国家探索游戏的用户，我希望当前国家的游戏封面与标记明确位于该国地图范围内，以便正确理解游戏与国家的归属关系。

**Why this priority**: 标记落在国界外会造成事实含义错误；瑞典等狭长或面积较小国家尤其容易出现该问题。

**Independent Test**: 选择瑞典，并覆盖面积较小、狭长、多岛和高密度游戏国家，逐一检查当前国家的所有可见标记与封面是否处于该国可用显示区域，且不会被误解为邻国内容。

**Acceptance Scenarios**:

1. **Given** 用户选择瑞典，**When** 国家聚焦与标记布局完成，**Then** 所有瑞典游戏标记都位于瑞典国界内的可用显示区域，不落入挪威、芬兰、波罗的海或其他邻近区域。
2. **Given** 所选国家边界狭长、分散或可用面积不足，**When** 游戏数量超过常规平铺容量，**Then** 系统采用紧凑、聚合、缩放或分层展示，仍保证每个可见标记的国家归属无歧义。
3. **Given** 用户在缩放、旋转或切换显示模式后返回所选国家，**When** 标记重新布局，**Then** 标记位置保持确定、稳定且仍符合该国边界约束，不发生随机漂移。

---

### User Story 4 - 统一且有辨识度的视觉体验 (Priority: P2)

作为游戏文化探索用户，我希望页面呈现深邃、现代、富有游戏感的视觉氛围，同时保持地球、国界、封面和文字清晰可辨，而不是被单一的暗黄或棕黄色覆盖。

**Why this priority**: 当前大面积黄褐色降低了层次、辨识度和品质感；视觉升级能强化产品定位，但应建立在核心交互正确和流畅的基础上。

**Independent Test**: 对首屏、全球视角、国家聚焦、右侧详情和控制状态进行视觉走查，并让目标用户完成“找到地球、选择国家、识别当前状态”任务后评价清晰度与吸引力。

**Acceptance Scenarios**:

1. **Given** 用户进入 Earth Explorer，**When** 查看首屏，**Then** 页面使用深空或夜景基调、冷色地球层次和克制的高亮色，黄褐色不再成为地球与主画布的主导色。
2. **Given** 页面同时显示海洋、陆地、国界、选中国家、游戏标记和面板，**When** 用户观察或交互，**Then** 各层级可凭颜色、明暗、尺寸或空间关系清晰区分，选中与悬停状态一目了然。
3. **Given** 用户阅读标题、统计、按钮和国家详情，**When** 处于默认、悬停、选中、禁用或加载状态，**Then** 文本和控件保持清晰可读，且视觉反馈一致、不依赖闪烁表达状态。
4. **Given** 用户开启减少动态效果的系统偏好，**When** 进入或操作页面，**Then** 仍能获得完整信息和明确反馈，非必要的持续动画与强烈过渡被抑制。

### Edge Cases

- 浏览器高度较低或发生窗口缩放时，首屏应优先保留完整地球和核心控制，次要统计信息允许折叠、压缩或移出首屏。
- 国家没有当前筛选条件下的游戏时，国家仍应成功聚焦并显示明确空状态，不保留上一个国家的标记或统计。
- 国家游戏数量超过可读容量时，应避免一次绘制所有封面造成遮挡或性能骤降，并提供数量真实的聚合表达。
- 面积很小、狭长、多岛或跨越日期变更线的国家，应采用与其地理形态相适应的可用显示区域，避免把标记误放到邻国或海洋。
- 用户在相机移动、标记加载或面板过渡期间重复点击同一国家或不同国家时，最终状态必须与最后一次有效输入一致。
- 游戏封面缺失、加载失败或加载较慢时，应使用稳定占位表达，不能引起地图尺寸跳变、闪屏或交互阻塞。
- 设备性能不足以维持完整视觉效果时，应优先保持输入响应、国家选择正确性和地图可读性，再降低非关键装饰效果。
- 移动端和窄屏布局不得因桌面首屏优化而退化：地球仍是主要区域，详情面板不得永久遮挡核心探索操作。

## Requirements *(mandatory)*

### Functional Requirements

- **FR-001**: 系统 MUST 在 1280×720、1440×900 和 1920×1080 桌面视口中，让主探索画布至少占首屏可见高度的 70%。
- **FR-002**: 系统 MUST 在用户首次进入时完整呈现地球主体，不得由标题、统计、导航、详情面板或视口边缘造成关键部分截断。
- **FR-003**: 系统 MUST 将标题、产品说明和全局统计收敛为辅助信息层级，使用户无需滚动即可开始旋转、缩放、重置或选择国家。
- **FR-004**: 系统 MUST 在窗口尺寸变化和受支持的响应式布局中持续保持地球为面积最大的单一内容区域。
- **FR-005**: 系统 MUST 提供统一的深空游戏地图视觉体系，清楚区分背景、海洋、陆地、国界、选中国家、游戏标记、面板和交互状态。
- **FR-006**: 系统 MUST 避免以大面积黄褐色作为地球和主探索画布的主导色，并使用克制的高亮色表达可交互、悬停和选中状态。
- **FR-007**: 系统 MUST 保证核心文字、按钮、数据与地图要素在所有常用状态下可辨识，并为仅靠颜色难以区分的状态提供额外视觉线索。
- **FR-008**: 系统 MUST 尊重用户的减少动态效果偏好，同时保留完整的导航、选中和加载反馈。
- **FR-009**: 系统 MUST 在连续旋转、缩放和相机聚焦过程中保持输入与画面连续，不因非关键装饰、标记或面板更新造成明显冻结。
- **FR-010**: 系统 MUST 在国家选择后 100 毫秒内给出可见响应，并在 700 毫秒内使目标国家、标题、统计、面板和标记达到一致的稳定状态。
- **FR-011**: 系统 MUST 将最后一次有效国家选择视为最终意图，取消或取代尚未完成的旧切换，防止旧状态覆盖新状态。
- **FR-012**: 系统 MUST 在国家切换期间保持地图连续可见，不得出现整屏白屏、黑屏、旧新画面往返或明显亮度闪烁。
- **FR-013**: 系统 MUST 确保所选国家的每个可见游戏标记落在该国的可用显示区域内，并且不会被视觉上误判为邻国内容。
- **FR-014**: 系统 MUST 对面积小、狭长、多岛或高密度国家采用确定性的紧凑、聚合、缩放或分层规则，以同时满足地理归属、可读性和流畅性。
- **FR-015**: 系统 MUST 在旋转、缩放、筛选、显示模式切换和重新聚焦后保持同一组标记的位置稳定，除非可用空间或筛选结果实际改变。
- **FR-016**: 系统 MUST 在国家没有匹配游戏、封面缺失或资源加载失败时显示稳定且明确的降级状态，不得沿用上一国家内容或阻塞地图操作。
- **FR-017**: 系统 MUST 限制同时呈现的高成本标记与非关键视觉效果，使游戏数量增长时仍保留真实数量提示、核心代表内容和交互响应。
- **FR-018**: 系统 MUST 保留现有国家探索、年份筛选、封面大小、显示模式、详情查看和返回入口的用户能力，不得因本次优化而丢失功能。

### Key Entities

- **探索视图状态**: 表示当前区域、当前国家、相机视角、缩放级别、显示模式、筛选条件和过渡阶段；任一时刻只能有一个对用户可见的最终选择状态。
- **国家可用显示区域**: 从国家地理边界中得到的、适合放置游戏标记的区域；需适应狭长、多岛和小面积形态，并排除容易造成邻国误判的位置。
- **游戏地图标记**: 代表单个游戏或游戏聚合的可交互视觉对象，关联一个国家、显示位置、视觉层级、封面或占位内容及选中状态。
- **国家切换请求**: 用户通过快捷按钮、国家列表或地图发起的聚焦意图；具有明确目标和先后顺序，最后一次有效请求决定最终展示状态。

## Success Criteria *(mandatory)*

### Measurable Outcomes

- **SC-001**: 在三个目标桌面视口中，100% 的首次进入测试都无需滚动即可看到完整地球主体、核心地图控制和国家信息入口，且主探索画布高度不低于视口的 70%。
- **SC-002**: 在基准设备上连续旋转和缩放 30 秒时，画面中位帧率不低于 55 帧/秒，95% 的采样时段不低于 45 帧/秒，且不存在超过 250 毫秒的可见冻结。
- **SC-003**: 在单次与快速连续国家切换测试中，100% 的操作在 100 毫秒内出现反馈、在 700 毫秒内完成一致状态呈现；连续 100 次切换无失败、回跳、整屏空白或闪屏。
- **SC-004**: 对瑞典、挪威、丹麦、荷兰、比利时、瑞士、日本、英国和韩国进行检查时，100% 的可见游戏标记均处于对应国家的可用显示区域内，且没有被测试者误认为属于邻国。
- **SC-005**: 在不少于 5 名目标用户的首屏任务测试中，至少 90% 的用户能在 5 秒内指出地球是页面主操作区，并在 10 秒内开始旋转或选择一个国家。
- **SC-006**: 在不少于 5 名目标用户的视觉评估中，至少 80% 的用户认为新版比当前截图中的黄褐色界面更清晰、更有吸引力且更符合“游戏地球探索”主题。
- **SC-007**: 在默认动态偏好和减少动态效果偏好下，100% 的核心探索任务均可完成，且选中、加载、空状态与错误状态都能被准确识别。

## Assumptions

- 本规格优化现有 Earth Explorer 入口，不以替换产品形态、增加后端服务或改变游戏国家归属数据为目标。
- 桌面验收以 1280×720、1440×900 和 1920×1080 为主要视口；移动端与窄屏需保持现有核心能力且不得明显退化。
- “基准设备”指 2021 年或之后上市、至少具备四核处理器、8 GB 内存、集成显卡和 60 Hz 显示器的桌面或笔记本电脑，并使用启用硬件加速的当前稳定版主流浏览器；同一轮前后对比必须使用同一设备和浏览器版本。
- 首屏可以压缩、折叠或重新安排标题、说明和统计信息，但这些信息仍应在页面中可访问。
- 标记越界的判定以用户看到的国家边界和可用显示区域为准；必要时允许用聚合标记代替全部封面平铺。
- 视觉方向默认采用深空或夜景基调、冷色地球层次和少量高亮色，中文为主要界面语言，英文用于专有名词或辅助信息。
- 性能降级优先级依次为：输入响应和状态正确性、地球与国界可读性、代表性标记、非关键装饰和持续动画。

## Dependencies

- 依赖现有 Earth Explorer 的国家、游戏、筛选和封面数据能够正常读取，且国家代码与地理边界可关联。
- 依赖现有国家列表、快捷国家按钮、地图选择、相机控制和详情面板继续提供一致的选择入口。
- 依赖规划与实施阶段建立可重复的桌面视口、基准设备、性能采样和国家边界验收方法。

## Scope Boundaries

- 本功能包含首屏信息层级与响应式排版、整体视觉体系、地球操控性能、国家切换一致性、闪屏消除和国家内标记布局正确性。
- 本功能不新增登录、后端数据库、在线推荐、生产级数据接口、社交能力或新的游戏数据字段。
- 本功能不要求移除 Game Chronicle、Earth Explorer Pro 或现有筛选与详情能力，也不改变游戏按主要开发商/工作室国家归属的产品规则。
